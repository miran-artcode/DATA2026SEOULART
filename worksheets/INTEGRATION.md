## A. 저장: 학습지 한 장 = 작업노트 한 건

`config/firestore.rules` 의 마지막 줄이 **모르는 컬렉션을 전부 막습니다.**

```
match /{document=**} { allow read, write: if false; }
```

새 컬렉션(`worksheets`)을 만들면 규칙 재게시 + `cloud-config.js` 수정 + 교사 대시보드 수정까지 번집니다.
그래서 학습지 한 장을 **작업노트 한 건**으로 저장합니다. 규칙이 요구하는 `userId` · `kind` 를 갖추고
`answers` 를 중첩 객체 하나로 넣으므로 `data.size() < 60` 조건도 통과합니다(최상위 필드 16개).

```js
{
  id: 'ws_2-3-k7f2_data-eye_s3',   // ★ 미리 정해진 id: 자동 저장이 겹쳐도 한 장에 한 건
  userId, by,                      // 별명(실명 아님): 교사 화면이 이것으로 조인한다
  klass: '2-3', code: '2-3·k7f2',  // 반 + 가명 코드
  kind: 'worksheet', unit: 'data-eye', sheet: 's3', session: 3,
  stage: 1,                        // 4단계 여정에서의 자리(숫자)
  procStage: 'make',               // 창작 7단계에서의 자리(키): metrics.js 의 D-1 이 쓴다
  title: '3차시 · 규칙 두 개 만들기',
  answers: { 's3.report.data_name': '…', 's3.selfcheck.why': 'good' },
  filled: 12, total: 24,           // 진행률을 매번 세지 않아도 되도록 저장 시점에 함께 적는다
  updatedAt
}
```

**id 를 미리 정하는 이유**: 자동 저장은 디바운스로 겹칠 수 있는데 id 없이 저장하면 그때마다 새 노트가
생겨, 교사 화면에서 같은 학생의 같은 차시가 여러 줄로 보이고 제출률이 어긋납니다.
로컬(`store.js`)도 클라우드(`setDoc … {merge:true}`)도 같은 id 면 덮어씁니다.

**공짜로 따라온 것**: `admin.html`·`portfolio.html`·`Store.exportAll()` 이 이미 notes 를 읽으므로,
저장이 시작되는 순간부터 취합·인쇄·내보내기가 동작합니다.

### ⚠ 저장소를 읽는 자리는 '학습지를 실제로 여는 순간'뿐이어야 합니다

클라우드 모드의 `listNotes` 는 **notes 컬렉션을 통째로 읽습니다**(`where` 절이 없습니다).
탭·스트립은 18개 화면에 늘 떠 있으므로, 그것들이 저장소를 읽으면 한 시간 수업에 학급 전체 노트를 수백 번 읽게 됩니다.

- **읽어도 되는 곳**: `worksheet.html`(답이 필요하다) · 서랍을 **연 순간**(`openDock`) · `admin.html`(교사가 한 번 본다)
- **읽으면 안 되는 곳**: 위치 스트립(`mountContext`) · 서랍 탭(`mountDock` 의 그리기) · 통합 여정(`mountJourney`)

읽은 결과는 `myNotes()` 안에서 **이 페이지가 사는 동안 한 번만** 가져옵니다(메모이즈). 그래서 서랍을 닫았다
다시 열어도 추가 읽기가 없습니다. 안 읽는 자리는 대신 **이 기기의 진행률 요약**
(`localStorage['dn_ws_prog']`, `{userId, sheets:{s1:{filled,total,pct}}, syncedAt}`)만 읽습니다.
요약은 저장할 때마다 갱신되고, 학습지 화면이나 서랍을 한 번 열면 저장소 원본으로 다시 맞춰집니다.

### 요약이 없는 기기는 지도 화면에서 한 번 되살립니다 (`ensureProgress`)

요약은 '쓴 기기'에만 남습니다. 그래서 답이 저장소에 멀쩡히 있어도 그 기기에서 학습지를 아직 안 열었으면
허브·여정이 전부 0으로 보였습니다. 실제로 겪는 세 경우:

- 학생이 다른 기기(집·다른 교실 컴퓨터)에서 연다
- 한 기기를 여러 학생이 나눠 쓴다 (다음 학생 차례)
- 교사가 **우수 사례 학급**을 불러와 학생 화면을 보여 준다 — 여덟 차시를 다 쓴 기록인데 허브는 '첫 차시'라고 말했다

`WS.ensureProgress(user)` 가 **요약이 없을 때만**, 그것도 **지도 화면(`hub.html`·`journey.html`) 두 곳에서만**
한 번 읽어 되살립니다. 18개 활동 화면의 탭·스트립은 여전히 저장소를 읽지 않습니다. 읽고 나면 `syncedAt`
표시를 남겨, 진행이 0인 학생에게 매번 다시 읽지 않습니다. 기기를 함께 쓰는 교실을 위해 요약은 `userId`
와 함께 저장되고, 다른 학생이면 무시하고 그 학생 것으로 다시 세웁니다.

**한 장만 집어 오는 `getNote` 를 만들지 않은 이유**: `store.js` 의 `call()` 은 클라우드에 없는 메서드를
조용히 로컬로 넘깁니다. 클라우드 수업에서 빈 답을 받아 들고 첫 타자에 그것을 덮어쓰면 학생이 쓴 것이 사라집니다.

### 이동 직전 입력

`beforeunload` 안에서는 클라우드 저장이 끝날 시간이 없습니다. 그래서 **저장 대기 중일 때 링크 클릭을 가로채**
저장을 마친 뒤 이동합니다. 가로채는 범위가 두 화면에서 다릅니다.

- `worksheet.html`: 문서 전체(캡처 단계). 그 화면은 학습지 한 장이 곧 화면 전부입니다.
- 도구 화면의 서랍: **서랍 안쪽만.** 도구의 캔버스·단추 위에 문서 단계 가로채기를 얹으면 도구가 이상하게 움직입니다.
  서랍 바깥으로 나가는 이동은 `beforeunload`·`visibilitychange` 가 받습니다(로컬 저장은 동기라 안전하고,
  클라우드는 마지막 1초 남짓을 잃을 수 있습니다 — 도구를 건드리지 않는 쪽을 택했습니다).

## B. 붙어 있는 자리

| 파일 | 하는 일 |
|---|---|
| `worksheet.html` | 학습지 화면(전체 보기·인쇄). 왼쪽 단원 차례 · 오른쪽 학습지 한 장 · 머리에 그 차시의 배우기·만들기·나누기 · 인쇄는 학습지만 |
| `js/worksheet.js` | `COURSE`(차시↔단계↔배우기·만들기·나누기 화면) · 한 장 쓰기 엔진(`attachSheet`) · 순차 진행 · 이월 한 줄 · **도구 옆 학습지 서랍** · 통합 여정 |
| `js/ui.js` | 상단 메뉴 다섯 묶음(오늘·8차시·도구함·내 기록·교사). 「8차시」 묶음을 `COURSE` 에서 자동 생성한다 |
| `hub.html` · `journey.html` | `WS.mountJourney()` 통합 여정(한 줄 = 한 차시: 배우기·만들기·나누기 + 학습지). **허브는 `{start:true}`** — 주연 카드도 줄 단추도 그 차시의 **첫 활동**으로 보내고 학습지는 거기서 옆에 펼쳐진다(둘이 다른 곳을 가리키면 학생이 또 헤맨다). `journey.html` 은 읽고 계획하는 화면이라 학습지 전체로 보내고, `WS.loadUnit()` 으로 unit.json 의 목표·확인 방법·루브릭도 그린다(여정 서술의 정본) |
| 척추 18개 화면(각 차시의 배우기·만들기·나누기 전부) | 끝에 `js/worksheet.js` + `WS.mountContext()`(위쪽 위치 스트립) + `WS.mountLauncher()`(= `mountDock`, 오른쪽 아래 학습지 서랍) |

### 학습지는 도구 쪽으로 온다 (`mountDock`)

예전 단추는 `worksheet.html` 로 **데려갔고**, 그 순간 만들던 것(불러온 그림·녹음·매핑 설정)이 화면과 함께
사라졌습니다. 학생은 도구에서 한참 만들다 마지막에 몰아 쓰거나 아예 쓰지 않았습니다.
이제 같은 화면 오른쪽에서 학습지가 펼쳐집니다.

- **한 장이다.** 서랍과 `worksheet.html` 은 `attachSheet` 하나·같은 노트 id·같은 저장 경로·같은 진행률을 씁니다.
  어디서 쓰든 교사 화면에는 한 줄로 모입니다.
- **도구를 건드리지 않는다.** 자기 마크업·자기 CSS 를 스스로 넣으므로 `site.css` 를 쓰지 않는 색 군집
  스튜디오에도 마크업 수정 없이 붙습니다. 무거운 것(렌더러·꾸러미 CSS·학습지 JSON)은 학생이 실제로 열 때 받습니다.
  꾸러미 CSS 는 `<link>` 가 아니라 **`@page` 규칙을 떼어 내고** `<style>` 로 넣습니다(서랍을 열었다고 그 화면의
  인쇄 여백이 달라지면 안 됩니다).
- **차시를 넘겨짚지 않는다.** 여러 차시가 함께 쓰는 화면(데이터 점 스튜디오·갤러리·리터러시)에서는 쓰기 전에
  묻고, 고른 차시를 주소(`?s=`)에 새겨 스트립·보내기 단추·기록 꼬리표까지 같은 차시를 말하게 합니다.
  링크와 달리 여기는 **쓰는** 자리라, 넘겨짚으면 답이 남의 차시 칸에 저장됩니다.
  차시를 고르는 일은 `pickSession()` 한 곳에서 하고 **화면을 새로 읽지 않습니다**(`history.replaceState`).
  위치 스트립의 차시 고르기도 같은 길을 씁니다 — 이미 CSV 를 올리고 매핑을 만들어 둔 학생이
  차시를 고르려다 그것을 잃으면, 학습지 단추에서 없앤 문제를 그 자리로 옮겨 놓는 셈입니다.
- **열어 둔 채 화면을 옮기면 다음 화면에서도 열려 있습니다**(`localStorage['dn_ws_dock']`, 넓은 화면에서만).
  '왔다갔다'가 사라지는 지점입니다.
- 서랍 머리에는 그 차시의 **배우기 → 만들기 → 나누기**가 모두 링크로 놓이고 지금 있는 화면이 켜집니다.
  꾸러미 JSON 의 `screens` 회색 글씨는 끕니다(`renderSheet(…, {hideScreens:true})`) — 같은 말이 두 번,
  그것도 한 번은 못 누르는 글씨로 나오던 자리였습니다.
| `admin.html` | **D-6 학습지 탭**: 차시별 제출률 · 학생×차시 격자 · 칸별 답 · CSV 2종 |
| `js/metrics.js` | 학습지 노트를 D-1(7단계 진행)·D-3(타임라인)에 반영. 노트가 가진 `klass` 로 가명 코드를 맞춘다 |
| `js/portfolio.js` | A4 포트폴리오에 차시별 완성도 + **차시마다 넘긴 한 줄** |
| `js/studio-data.js` · `data/bodyfat.csv` | 6차시 자료를 샘플 목록에 등록(‘숫자가 사람을 말할 수 있을까’) |

`COURSE` 는 **배치를 바꾸는 단 한 곳**입니다. 차시를 다른 단계·다른 화면에 걸고 싶으면 그 표만 고칩니다.

### 차시 순서 = 단계 순서 (하나의 척추)

학습지끼리 **‘다음 시간으로 넘기는 한 줄’**이 `s1→s2→s3→s4→s5→s6→s8`, `s7→s8` 로 이어져 있고,
4단계 여정의 번호도 그 순서를 따릅니다: 그림(1단계·1~3차시) → 내 소리(2단계·4차시) →
내 사진(3단계·5차시) → 사회(4단계·6차시~). 순차 진행의 척추는 차시 번호 하나이고,
각 차시의 단계 배지·배우기·만들기·나누기 화면은 모두 `COURSE` 표에서 나옵니다.
(과거에는 지도가 사진(2단계) → 소리(3단계)로 학습지와 어긋나 있었는데, 학습지의 이월 사다리
(소리에서 ‘세기’를 익힘 → 내 삶에 적용 → 타인의 데이터로 확장)에 맞춰 정렬했습니다.)

## C. 원본 꾸러미와 달라진 곳

이 폴더는 `art-ai-education-lab/content/worksheets` 의 사본입니다. 붙이면서 **내용 한 곳**을 고쳤습니다.

- `unit-data-eye/07-words-in-color.json`: 7차시 ‘낱말 구름 스튜디오’ 화면이 **생겼습니다**
  (`studio-word.html`). `screens[0]` 을 `page: 'studio-word.html', exists: true` 로 바꾸고 `gap`·`gaps` 를 지웠습니다.
  → **원본 꾸러미에도 같은 수정을 넣어 두면** 두 곳이 어긋나지 않습니다.
- `preview.html` · `roster/` · `instances/` 는 가져오지 않았습니다(작업용·학생 자료).
  종이 인쇄가 필요하면 원본 폴더에서 `node build.mjs --instances` 로 만들어 인쇄하세요.

## D. 고치고 나서 하는 일

```bash
node worksheets/build.mjs        # 내용 검사 + manifest 갱신 (경고 0 이 목표)
node worksheets/smoke.mjs        # 9장이 모두 그려지고 저장 경로가 맞는지
node tools/check-spine.mjs       # 척추(COURSE)와 화면이 어긋나지 않았는지
```

`build.mjs` 를 돌리지 않으면 새 칸이 **진행률·교사 화면·CSV 에 잡히지 않습니다**(색인이 옛것이므로).

### 확인 순서(수업 전 1분)

- 학생: `worksheet.html?s=s1` → 몇 칸 쓰고 새로고침 → 그대로 남아 있는가
- 서랍: `studio-data.html?s=s3` → 오른쪽 아래 📄 → 도구 옆에서 몇 칸 쓰기 → `worksheet.html?s=s3` 에 같은 답이 있는가
- 서랍(차시 물음): `studio-data.html`(`?s=` 없이) → 📄 → **차시를 묻는가**(바로 펼치면 안 된다)
- 교사: `admin.html` → 📄 학습지 탭 → 차시 표·격자에 보이는가 → 답안 CSV 가 받아지는가
- 인쇄: 학습지 화면에서 🖨 → A4 에 학습지만(내비·차례 없이) 나오는가
- 오프라인: 인터넷 없이도 열리는가(`Store` 로컬 폴백 · 주소 끝에 `?local=1` 로 강제 가능)
