# 오늘의 시선

> 시대 문제를 데이터로 읽고 예술로 번역하는 교육용 소프트웨어

> AIEDAP · 2022 개정 교육과정(미술·정보) AI 융합수업 지원 **멀티페이지 수업 사이트**
>
> 🔒 **블라인드 안내**: 이 사본은 심사 제출용으로 **저작자(개인)·소속 학교 정보를 가려 둔 판본**입니다.
> 저작권(© 2026 「오늘의 시선」 데이터 미디어아트 스튜디오)은 그대로 유효하며, 저작권자 정보는 요청 시 제공됩니다.
> 두 수업을 하나의 스튜디오로: **「그림을 점으로 분해해 다시 연주하기」**(색 군집) +
> **「데이터가 춤추는 점」**(데이터 매핑).

그림·데이터를 **여러 알고리즘으로 분석**하고, 학생이 **의도와 조작 설정**으로
인터랙티브 제너러티브 미디어아트로 **재창조**합니다. 설치·서버·계정 없이 `index.html`로 시작합니다.

## 단원의 뼈대: 목표를 먼저 정하고 짠 하나의 순서

이 단원은 **목표를 먼저 정하고, 그것을 확인할 방법을 정한 다음, 그 둘에 맞춰 차시를 짰습니다**
(교육학에서는 이를 "백워드 설계"라 부르지만, 사이트 화면에는 이 용어를 쓰지 않고 항상
"어디로 가나 · 무엇을 보면 아나 · 어떻게 가나"라는 평범한 말로 풉니다). 세 층의 원본이 나뉘어 있습니다.

| 층 | 원본 | 학생 화면 |
|---|---|---|
| ① 어디로 가나 | `worksheets/unit-data-eye/unit.json` 의 큰 개념·이 단원이 남기는 힘·되풀이해 묻는 질문 | `journey.html` 상단(단원의 결론은 교사 전용, 8차시에 학생이 스스로 도달) |
| ② 무엇을 보면 아나 | 같은 파일의 마무리 과제·루브릭 4수준·세 갈래로 남기는 것 + 학습지의 칸 | `journey.html` 가운데 · 학습지·대시보드·포트폴리오로 자동 취합 |
| ③ 어떻게 가나 | `js/worksheet.js` 의 `COURSE` 표(차시 ↔ 단계 ↔ 배우기·만들기·나누기 화면) | 허브·여정 지도의 **통합 여정**(한 줄 = 한 차시) · 상단 「8차시」 메뉴 · 척추 18개 화면의 **위치 스트립** |

**순서의 척추는 차시 번호 하나**입니다. 학습지끼리 '다음 시간으로 넘기는 한 줄'이 차시 순서로
이어져 있고, 4단계 여정은 그 차시들을 **주체성 기준으로 묶은 것**이라 순서가 서로 같습니다.
진행의 기준은 주체성 하나: 교사가 준 것에서 시작해 내 소재로, 내가 정한 문제로 넘어갑니다.

| 단계 | 차시 | 화면 | 학생이 정하는 것 | 새로 배우는 개념 |
|---|---|---|---|---|
| 1 그림 | 1~3차시 | `lab.html` → `studio-color.html` → `studio-data.html` | 매핑·규칙 | K-means, 대표색, 매핑 |
| 2 내 소리 | 4차시 | `studio-sound.html` | **무엇을 남길지** | 음량·주파수 대역·날카로움·변화량·음높이·시계열 |
| 3 내 사진 | 5차시 | `studio-life.html` | **무엇을 셀지·무엇을 숨길지** | 거의 없음(1단계 이미지 통계를 그대로 재사용 · 재현과 손실의 성찰) |
| 4 사회 | 6차시~ | `project.html` · `society.html` | **문제 자체** | 공공데이터 탐색·정제·CSV, 기본값 되묻기 |

소리(4차시)를 삶(5차시)보다 앞에 둔 것은 학습지의 연결 때문입니다. 소리 차시의 넘기는 한 줄이
**"내 삶에서 세어 보고 싶은 것 한 가지는?"** 이어서, '세기'를 소리에서 익힌 뒤 내 삶에 적용하고
(5차시), 이어서 타인의 데이터(6차시·사회)로 나아가는 사다리가 됩니다. 삶 차시는 새 개념이
거의 없어 **재현·숨긴 선택의 성찰**에 집중할 수 있습니다.

`studio-data.html`(데이터 점)과 `studio-object.html`(객체 감지)은 **도구**여서 순서가 없습니다.
2·3·4단계가 만든 데이터는 모두 데이터 점 스튜디오로 흘러 들어가 작품이 됩니다.

**판별은 첫 결과가 나온 직후에** 옵니다. 질문 카드가 스튜디오 안에서 되묻고, 비평·객체 감지·
리터러시는 통합 여정에서 **그 차시의 '배우기' 칸**으로 끼워져 있습니다(1차시 리터러시 1·2장,
3차시 데이터 비평, 5차시 객체 감지, 6차시 리터러시 5장 …).

**학생이 서 있는 화면이 스스로 말합니다.** 척추 18개 화면 맨 위에 **위치 스트립**이 뜨는데,
그 문구는 손으로 적은 것이 아니라 `COURSE` 표에서 만들어집니다.

```
[3차시] 1단계 · 규칙 (만들기)  「규칙 두 개 만들기」
앞: 2차시 · 1단계 · 그림    다음: 나누기 · 작업 노트 →     [📄 3차시 학습지]
```

여러 차시가 함께 쓰는 화면(데이터 점 스튜디오·갤러리·리터러시)은 주소의 `?s=sN` 으로 차시를 받고,
없으면 **추측하지 않고 고르게 합니다**(틀린 확신은 한 번 더 묻는 것보다 나쁩니다).
리터러시처럼 특정 장을 약속하는 링크는 `?s=s6#ch5` 처럼 도착 지점까지 싣습니다.
스트립은 **로그인 없이도** 뜨고, 진행률(%)만 로그인한 학생에게 덧붙습니다.

이 구조가 어긋나지 않았는지는 `node tools/check-spine.mjs` 가 확인합니다(앵커가 실제로 닿는지,
척추 화면이 스트립을 부르는지, 들어갈 길 없는 고아 화면이 없는지, 학습지 종이와 화면 목록이 같은지).

## 핵심 기능

### 1) 알고리즘 분석실 (`lab.html`): 한 그림, 일곱 가지 알고리즘
한 그림을 7가지로 분석하고, 각각 **차트 + 재창조 결과 + ⓘ설명 + “이 분석이 놓친 것” + 해석 메모**(→ 리포트로 모임).

| 알고리즘 | 재창조 | 비고 |
|---|---|---|
| ① K-means 색 군집화 | 대표색 점 치환 | 핵심 |
| ② 색 히스토그램 | 포스터화 | 핵심 |
| ③ 명도·노탄 | 흑백 명암지도 | 핵심 |
| ④ 에지(Sobel) | 선 드로잉 | 핵심 |
| ⑤ 중앙값 분할(Median Cut) | 또 다른 색 요약 | 심화 · K-means와 비교 |
| ⑥ 격자 평균·모자이크 | 픽셀아트 | 심화 |
| ⑦ 구도 분석 | 무게중심·삼분할 | 심화 |

**색 분석 차트 6종**: 비율 도넛 · 정렬 막대 · 색공간 산점도(군집 중심 표시) · RGB 채널 히스토그램 · 색상환 분포 · 명도 히스토그램/톤커브. 각 차트 옆 **해석 메모**가 자동으로 리포트(부록 A)로 모입니다.

**명화 = 실제 퍼블릭 도메인 작품(위키미디어 공용, 공교육용)**: 고흐 별이 빛나는 밤 · 쇠라 그랑드자트섬의 일요일(점묘) · 모네 인상·해돋이 · 호쿠사이 큰 파도 · 다 빈치 모나리자 · 베르메르 진주 귀고리 소녀 · 클림트 키스 · 뭉크 절규 · 칸딘스키 구성 7 · 몬드리안 구성. 인터넷이 없으면 비슷한 절차적 그림으로 자동 대체. 사조와 분석을 잇습니다.

### 2) 색 군집 스튜디오 (`studio-color.html`)
명화를 K-means로 분석 → 대표색 점으로 치환 → 마우스(밀기/끌기/부풀리기/흩뿌리기·클릭 폭발)와
마이크(볼륨→진동·확산·크기, 주파수→밝기별 색 군집 반응)로 ‘연주’. 2D 점/선 + **3D 조각**(밝기→깊이).
*기존 단일 파일 도구를 그대로 편입했습니다. 사이트 없이도 단독·오프라인으로 동작(백업).*

### 3) 데이터 점 스튜디오 (`studio-data.html`)
우리 데이터(감정·기온·걸음·소음/직접 입력/CSV)를 점의 **크기·속도·방향(벡터)·밀도·투명도·형태(△○□)**로 변환해 움직이는 작품으로.
매핑 규칙 **2안(A/B) 비교**, 의도·근거를 채워야 전시 가능(근거가 먼저).
**데이터 선택 기록(제작 문서)**: 감각먼저 → 무엇을 셌나/일부러 뺐나(숨긴 선택) → 왜 이 척도·색인가 → 데이터가 놓친 ‘내 삶의 진실’(메타비평). 〈Dear Data〉·데이터 휴머니즘을 ⓘ로 연결해, 데이터를 ‘비평 대상이자 창작 재료’로 다룹니다.

### 3.5) 낱말 구름 스튜디오 (`studio-word.html`): 자연어 분석 → 굿즈
작가 감상문·작가 정보를 **자연어 분석**(토큰화·불용어·한국어 조사 다듬기)해 낱말 **빈도→글자 크기**로,
글자 **색은 그 작가 그림의 대표색(K-means)·비율 순**으로 입히고, 낱말을 **모양 틀**(원·하트·이니셜·업로드 실루엣)에
**나선/격자 충돌 패킹**으로 채웁니다. 완성한 구름은 **엽서(앞=구름 / 뒤=편지·주소 칸 + 원본 그림)·카드·책갈피·스티커** 같은
**실생활 굿즈**로 인쇄용 고해상 PNG 내보내기. *분석 → 창작 → 실물*을 한 흐름으로. (위키백과 요약 가져오기는 온라인 선택, 오프라인이면 직접 입력.)

### 4) 배우기·나누기
- **배움터**: 7개 알고리즘 + 데이터 매핑 개념을 쉬운→깊은 설명으로. 미술사 다리(쇠라·로스코·옵아트·제너러티브).
- **갤러리**: 작품 감상 + **구조화된 피드백(의도 전달/근거/인터랙션/윤리)** → 받은 학생이 2차 개선(순환).
- **작업 노트**: 작업·버전·성찰 타임라인. “AI가 도운 것 / 내가 결정한 것” 기록.
- **분석 퀴즈(`quiz.html`)**: 그림을 분석해 ‘지배색·색채조화·색온도·구도’ 문제를 자동/직접 출제 → 친구가 풀어 점수·순위. 조형 요소 태그·해설로 감상·분석을 게임처럼.

### 4-b) 학습 데이터 대시보드와 AI 리터러시: 판단의 과정을 남기기

**무엇을 보고, 무엇을 의심하고, 무엇을 고르고 버렸는지**가 화면에 기록되고,
교사 화면에서 지표로 읽히고, 학생에게 포트폴리오로 돌아옵니다.

**① 학습 로그 (`js/log.js`)**: **판단의 행동 11가지만** 남깁니다. 화면 이동과 클릭은 기록하지 않습니다.
`view · analyze · map_apply · ab_switch · coach_ask · coach_answer · note_save · revise · exhibit · critique_write · reflect_submit`
각 기록은 창작 과정 **7단계**(감각·문제 → 의도 → 작업 → 판별 → 선택·수정 → 공유 → 책임·성찰) 중 하나에 붙습니다.

**② 판단 흔적 위젯 (전 스튜디오 공통)**
- **질문 카드 4종**(`js/cards.js`): 조형적 읽기 · 그럴듯함 판별 · 결정의 근거 · 기본값 되묻기.
  지금 화면 상태(팔레트·K·매핑 규칙)를 읽어 되묻고, 학생이 남긴 한 줄을 기록합니다.
- **버전 스냅샷 · A/B 비교**(`js/version.js`): 저장할 때마다 설정+작은 썸네일을 쌓고,
  두 버전을 좌우로 놓고 “무엇을 왜 바꿨는가”를 한 줄로 남깁니다(작품당 최근 8개 보관).
- **창작 진술문(150자)**: 리터러시 7장에서 작성 → 작품 페이지·키오스크·포트폴리오에 함께 표시.

**③ AI 리터러시 7장 (`literacy.html`)**: 각 장이 **읽기 → 직접 해 보기 → 한 줄 답하기** 3단.
1 픽셀 값 읽기 · 2 K를 밀며 사라지는 색 · 3 같은 조건 5회 생성의 닮음 · 4 **우리 반 유사도** ·
5 무엇을 셀 것인가(신체측정) · 6 자료 자동 점검 · 7 창작 진술문.
※ 3장은 실제 모델을 부르지 않는 **시뮬레이션**이며(오프라인 원칙), 화면에도 그렇게 밝힙니다.

**④ 교사 대시보드 (`admin.html`)**
- **D-1 진행 현황**: 7단계별 도달 인원 막대(막대를 누르면 해당 학생)
- **D-2 판단 지표**: 비교 횟수 · 수정 횟수 · 근거 작성률 · 코치 응답률 · 비평 · 성찰 제출률
- **D-3 학생 타임라인**: 의도 → 첫 결과 → 판별 한 줄 → 수정 → 최종 → 성찰(과정중심평가 근거)
- **D-4 학급 유사도 지수**: 작품의 **색 분포(64구간 히스토그램) 65% + 매핑 규칙 35%**로 서로 닮은 정도를
  0~100으로. 주성분 2축 산점도와 **가장 닮지 않은 3점(비전형)**을 함께 보여 줍니다.
  지수가 높다 = 자동 추천을 그대로 쓴 학생이 많다는 수업 진단 신호이자, 리터러시 4장의 실습 재료입니다
  (생성형 AI가 개인 창의성은 올리되 집단 참신성은 낮춘다는 보고(Doshi & Hauser, 2024)를 우리 반 데이터로 확인).
- **D-5 내보내기·보관**: 학급 지표 CSV · 학습 로그 CSV · 유사도 CSV · 포트폴리오 A4 인쇄 · 원자료 JSON
- **D-6 학습지**: 차시별 제출률·평균 완성도·자기점검 분포 · 학생 × 차시 격자 · 한 질문을 학급 전체로 모아 보기 ·
  제출 현황 CSV · 답안 CSV(칸·증거층·루브릭 대상 포함) → 아래 **4-c**

**⑤ 학생 포트폴리오 (`portfolio.html`)**: 7단계 진행 · 판단 지표 · 작품과 진술 · 수정 근거 ·
질문 카드 한 줄 · 리터러시 답 · **학습지 차시별 기록** · 성찰을 **A4 한 장**으로. 교사는 대시보드에서 `?uid=…`로 엽니다.

### 4-c) 학습지: 차시마다 한 장, 쓰면 그대로 데이터가 된다

수업의 순서를 사이트가 들고 있게 만든 층입니다. **학습지 한 장 = 한 차시**이고,
학생이 쓰는 즉시 자동 저장되어 **교사 대시보드 · 포트폴리오 · CSV**로 이어집니다.

```
worksheet.html            학습지 화면 (왼쪽 단원 차례 · 오른쪽 학습지 한 장 · A4 인쇄)
js/worksheet.js           차시 ↔ 4단계 ↔ 화면을 잇는 표(COURSE) · 자동 저장 · 순차 진행
worksheets/               내용 꾸러미: 내용(JSON)과 표시(렌더러)를 나눠 둔 폴더
  manifest.json           자동 생성 색인(칸 163개 · 라벨 · 증거층 · 루브릭 대상 68개)
  build.mjs · smoke.mjs   내용 검사 + 색인 갱신 / 렌더러 시험 (node 로 실행)
  render/                 렌더러 한 벌(의존성 0 · 화면과 A4 인쇄를 같은 코드로)
  unit-data-eye/          단원 「오늘의 시선」 · 표지 + 8차시 + 6차시용 자료(bodyfat.csv)
```

- **내용을 고치는 법**: `worksheets/unit-data-eye/NN-*.json` 을 고치고 `node worksheets/build.mjs`.
  검사(없는 개념·어긋난 저장 경로·중복 칸)를 통과해야 색인이 갱신됩니다. 코드는 건드리지 않습니다.
- **저장**: 학습지 한 장은 **작업노트 한 건**(`kind:'worksheet'`)으로 저장됩니다.
  새 컬렉션을 만들지 않으므로 `firestore.rules`·`cloud-config.js` 를 손대지 않아도 되고,
  노트를 읽는 교사 화면·포트폴리오·전체 내보내기가 **저장하는 순간 그대로 취합**합니다.
  노트 id 는 `ws_<가명코드>_<단원>_<차시>` 로 미리 정해져, 자동 저장이 겹쳐도 한 장에 한 건만 남습니다.
- **순서**: 앞 차시를 40% 넘게 채우면 다음 차시가 열립니다(결석·보충이 있으므로 잠금은 안내일 뿐 막지 않습니다).
  차시 끝의 **‘다음 시간으로 넘기는 한 줄’**은 다음 차시 머리에 다시 떠서, 종이를 넘겨 보던 동작을 화면에서도 잇습니다.
- **어디서 여는가**: 허브의 차시 묶음, 상단 **내 기록 → 학습지**와 **8차시 → 그 차시 줄**, 위치 스트립의 단추,
  그리고 **그 차시가 쓰는 화면 오른쪽 아래**에
  뜨는 `📄 N차시 학습지` 단추. 도구 옆에 종이가 놓여 있는 모양입니다.
- **교사 화면(D-6)**: 차시별 제출률·평균 완성도·자기점검 분포 / **학생 × 차시 격자**(칸을 누르면 그 학생의 답) /
  **한 질문을 학급 전체로 모아 보기** / **제출 현황 CSV**와 **답안 CSV**(한 줄에 한 칸 · 증거층 · 루브릭 대상 표시).

> 차시 순서와 4단계 순서는 **같습니다**(그림 1~3차시 → 소리 4차시 → 삶 5차시 → 사회 6차시~).
> 순차 진행의 기준은 차시 번호이고, 각 차시에 단계 배지가 달려 어느 도구를 쓰는지 알립니다.
> 차시마다 배우기·만들기·나누기 화면 묶음이 정해져 있어 허브·여정 지도·학습지 머리에 함께 뜹니다.
> 배치를 바꾸려면 `js/worksheet.js` 의 `COURSE` 표 한 곳만 고치면 됩니다.

### 4-d) 우수 사례 학급(가상): 빈 화면이 아니라 채워진 화면으로 보여 주기

수업을 처음 여는 자리에서는 저장소가 비어 있어 갤러리도 대시보드도 빈 화면입니다.
그래서 **여덟 명이 8차시를 마친 가상 기록** 한 벌을 함께 둡니다. 실제 학생의 기록이 아니고
실명·학교 정보도 없습니다.

```
data/showcase-class.json     자료 한 벌 (전체 내보내기와 같은 모양)
js/showcase.js               실어 주는 층: 처음 열 때 자동으로 한 번 · Store 읽기를 감싸 순서를 보장
tools/make-showcase.mjs      만드는 쪽. node tools/make-showcase.mjs
tools/showcase/personas.mjs    여덟 명이 쓴 말(학습지 163칸·작가노트·비평의 원본)
tools/showcase/png.mjs         썸네일·원본 그림을 브라우저 없이 굽는 팔레트 PNG 인코더
tools/check-showcase.mjs     검사. node tools/check-showcase.mjs
```

- **아무것도 누르지 않아도 보입니다**: `js/showcase.js` 가 척추 화면 전부에 실려 있어, **처음 열 때 한 번**
  자료를 저장소에 싣습니다. 그래서 갤러리·키오스크·작품 페이지·포트폴리오·교사 대시보드가 처음부터
  채워진 화면으로 열립니다. 페이지마다 코드를 고치지 않으려고 **`Store` 의 읽기 메서드를 감싸** 첫 조회가
  적재를 기다리게 했습니다(목록을 먼저 그려 놓고 자료가 뒤늦게 오는 사고가 없습니다).
  자동 적재를 **하지 않는** 경우는 다섯입니다: ① 이미 실은 뒤 ② 교사가 지운 뒤(다시 실리지 않습니다)
  ③ 클라우드(학급 공유) 모드 — 여럿이 함께 쓰는 저장소를 말없이 건드리지 않기 위해서
  ④ **이미 학생 기록이 있는 기기** — 채울 빈 화면이 없는 자리입니다. 그런데 이 자료는 1MB가 넘어,
  밀어 넣으면 브라우저 용량 한계에 닿고 `js/store.js` 의 안전판이 자리를 만들려고 학생의 학습 로그를
  절반 버립니다. 얻을 것이 없는 자리에서 남의 기록을 지울 수는 없습니다(그 기기에서는 교사가 단추로 직접 부릅니다)
  ⑤ **앞서 실패한 뒤** — 시도했다는 표시를 먼저 남깁니다. 표시가 없으면 실패가 화면을 열 때마다
  되풀이되고 그때마다 용량 정리가 한 번씩 더 일어납니다. 두 번까지만 시도합니다.
- **가상 기록임이 화면에 보입니다**: 갤러리 명제·상세 보기, 작품 페이지, **키오스크 전시**에 `예시` 배지가 붙습니다.
  QR 로 작품 페이지만 보는 관람객도, 전시장 화면 앞에 선 관람객도 실제 학생 작품과 구분할 수 있어야 하기 때문입니다.
- **직접 다루는 법**: 교사 대시보드 → **데이터 · AI 설정** 탭. 저장 방식에 따라 두 갈래입니다.
  | 단추 | 어디에 들어가나 | 누가 보나 |
  |---|---|---|
  | `🎓 이 기기에 다시 불러오기` | 이 브라우저 저장소 | 이 기기에서만 |
  | `☁️ 클라우드에 올려 모두에게 보이기` | 학급 공유 데이터베이스 | 어느 기기에서든 |

  **클라우드(Firebase) 모드로 배포한 사이트에서는 「이 기기에만 불러오기」가 화면에 보이지 않습니다.**
  자료는 브라우저에 들어가는데 화면은 클라우드를 읽기 때문입니다. 그때는 `admin.html?local=1` 로 열어
  이 기기 자료를 보거나, `☁️ 클라우드에 올리기`를 쓰세요. 대시보드가 지금 어느 쪽인지 화면에 적어 둡니다.

  `🧹 우수 사례만 지우기` 는 **클라우드와 이 기기 양쪽에서** `demo` 표시가 붙은 것만 걷어 냅니다
  (실제 학생 기록은 그대로 남습니다). 다만 **또래 비평·퀴즈 답안은 되돌릴 수 없습니다** —
  `firestore.rules` 가 '기록 보존'을 위해 그 둘의 삭제를 막아 두었기 때문입니다. 그래서 올릴 때
  따로 한 번 더 물어보고, 취소하면 나머지만 올라갑니다(갤러리에 또래 비평만 비어 보입니다).
  학생 화면을 보여 줄 수 있도록 별명 계정(PIN `0000`)도 함께 만듭니다.
- **학생 화면 보는 법**: 불러오면 그 자리에 **여덟 명이 이름·반과 함께** 나열됩니다. 누르면 그 학생으로
  로그인해 허브로 건너갑니다(관리자 잠금은 풀린 채라 언제든 대시보드로 돌아옵니다).
  허브·여정의 **차시 진행률까지 바로 채워집니다** — 기기에 요약이 없으면 저장소에서 한 번 되살리기
  때문입니다(`WS.ensureProgress`). 학생이 다른 기기에서 열거나 한 기기를 여러 학생이 나눠 쓸 때도 같습니다.
- **들어 있는 것**: 작품 48점(색 군집·데이터 점·낱말 구름·사회 분석) · 학습지 72장(163칸을 모두 채운) ·
  작업노트·성찰·진술문 96건 · 또래 비평 16건 · 학습 로그 360건 · 버전 스냅샷 62건 · 분석 퀴즈 4문항.
  갤러리·키오스크·작품 페이지·포트폴리오·D-1~D-6 지표가 전부 채워집니다.
- **한 사람이 한 질문을 8차시 내내 끕니다**: 아빠의 한 달 코골이(30밤) · 신체측정 252명의 평균 밖 ·
  지진 규모의 로그 눈금 · 챗봇에게 물은 것 · 밝기로 잰 기쁨 · 퍼센트가 지운 사람 수 등.
- **다시 만들 때**: `node tools/make-showcase.mjs` → `node tools/check-showcase.mjs`.
  난수와 시각이 고정되어 있어 **다시 실행해도 파일이 바이트까지 같습니다**(무엇이 바뀌었는지 보이도록).
  검사는 JSON 이 열리는지가 아니라 *화면에서 제대로 보이는지*를 봅니다 — 학습지 칸 경로,
  차시 완료 기준(60%), 노트 id 모양, 로그 action·stage, 매핑이 가리키는 열의 존재, 범주 색 누락, 중복 id.

#### 개인정보·윤리 (기능으로 구현)
| 항목 | 처리 |
|---|---|
| 로그인 | **학번 + 별명 + PIN**. 사이트 어디에도 **실명을 받지 않습니다**. 작품·갤러리·전시·피드백에 보이는 이름은 언제나 별명이고, 반(2-3)은 학번에서 자동으로 읽습니다(`20307` → `2-3`). `2-3-07`·`2307`·`20307`은 한 계정으로 모입니다 |
| 식별 정보 | **가명처리**. 로그·버전에는 학번도 별명도 저장하지 않고 반 + 가명 코드(예: `2-3·k7f2`)만 남깁니다. 코드는 `학번#별명`의 단방향 해시이지만 길이가 짧아, **학급 명단을 가진 교사만** 대조할 수 있는 수준입니다(완전 익명화가 아님). 교사 화면은 로그가 아니라 작품 데이터의 별명과 조인해 표시합니다 |
| 학습지 | 답은 **별명 + 반 + 가명 코드**로만 저장합니다(실명 칸 없음). 표지의 이름 칸도 **학번 코드**를 받습니다. 종이 사본을 만드는 `roster/*.csv`·`instances/` 는 저장소에 올라가지 않습니다(`worksheets/.gitignore`) |
| 원본 자료 | 음성·영상·사진은 브라우저 안에서만 처리(마이크 소리는 저장·전송 없음) |
| 보관 기간 | 대시보드 **‘단원 종료 후 학습 로그 정리’** 버튼(타이핑 확인 필요 · 작품·노트는 보존) |
| 공개 동의 | 작품마다 `consent` 표시. 끄면 **키오스크 전시·포트폴리오 인쇄에서 자동 제외**(기존 작품은 동의로 간주) |
| 외부 모델 | 실제 모델 코치를 켤 때 약관·연령·키 노출 경고를 대시보드에서 강제 표시 |

### 5) 전시·발표 모드: 키오스크 · QR · 감상·비평
실제 전시회를 위한 흐름입니다. **창작 → 전시 → 감상 → 비평**이 하나로 이어집니다.
- **키오스크 슬라이드쇼(`exhibit.html`)**: 큰 화면용 전체화면 전시. 작품 + 작가노트(의도·데이터·알고리즘) + **작품별 QR**을 자동으로 넘기며 보여줍니다(←/→·Space·F 단축키, 자동 넘김).
- **QR → 작품 단독 페이지(`work.html`)**: 관람객이 휴대폰으로 QR을 찍으면 그 작품 페이지가 열리고, **감상·비평을 직접 남깁니다**(로그인 없이 관람객 이름으로 가능).
- **감상·비평은 미술비평 표준 ‘펠드먼 4단계’**: ① 기술(무엇이 보이나) → ② 분석(색·명도·구도) → ③ 해석(의미·의도) → ④ 평가(근거 있는 판단). 가벼운 ‘별점+한마디’도 가능.
- **도슨트(작품 해설) 자동 생성**: 의도·데이터·알고리즘 설정을 읽어 한국어 해설을 만들어 작품 페이지·키오스크에 표시합니다.
- **작가의 과정·성찰 노출**: 학생의 성찰·분석 메모를 작품 페이지(키오스크 teaser)에 함께 전시합니다. 학습 과정도 작품의 일부입니다.
- **큐레이션(교사)**: 교사 대시보드에서 작품마다 **전시 순서·테마**를 지정 → 키오스크가 순서대로 보여주고 테마별로 필터합니다.
- QR 주소는 자동(현재 접속 주소)이며, 배포/교실 LAN 주소로 바꿀 수 있습니다(🔗 버튼). 같은 네트워크/링크면 관람객 비평이 실시간(클라우드)으로 모입니다.

> 🔒 **교사 대시보드**(`admin.html`)는 관리자 비밀번호로 잠겨 있습니다(관리자 계정 정보는 블라인드 처리). 정적 사이트의 *가벼운 잠금*(클라이언트 측, SHA‑256 해시 비교)이므로 강한 보안이 아니며, 민감정보는 올리지 마세요.

### 6) AI 감상 코치: 답 대신 질문하기
팔레트·K·N·규칙·학생 의도를 읽어 **근거를 캐묻는 질문**을 생성합니다(‘AI 맹신 금지’ 가치).
- **기본: 완전 오프라인**(인터넷·키 불필요). 8명이 동시에 써도 오류 없음.
- **선택: 실제 모델 호출**. 프리 티어 한도(분당 요청 5·입력 10K·출력 4K)를 `ratelimit.js`가 보호하고,
  한도 초과/네트워크 오류 시 **자동으로 오프라인 질문으로 폴백**.

### 가장 쉽게
`index.html`을 브라우저로 엽니다(인터넷 불필요). p5.js는 `vendor/`에 동봉되어 **오프라인 동작**.

### 로컬 서버(마이크·녹화 안정)
```bash
python3 -m http.server 8000   # → http://localhost:8000
```

### 온라인 전시 (GitHub Pages · 자동 배포)
`.github/workflows/pages.yml`가 푸시할 때마다 자동 배포합니다. 발행 주소(프로젝트 페이지):
**`https://<계정>.github.io/<저장소>/`** (실제 발행 주소는 블라인드 처리)
- 워크플로가 Pages 자동 활성화를 시도합니다. 만약 막히면 한 번만 **Settings → Pages → Source = “GitHub Actions”** 로 지정하세요.
- HTTPS라 마이크·녹화·클라우드가 정상 동작하고, 키오스크 QR도 이 주소를 가리킵니다.

## 실시간 클라우드 공유: 한 링크에서 학급 전체 [연동됨]

`config/cloud-config.js`가 Firebase 프로젝트 **`data-art-canvas`**(Firestore)에 연결되어 있어,
모든 페이지가 자동으로 실시간 공유 모드로 동작합니다. 설정 전/네트워크 불가 시에는 **로컬 저장으로 자동 폴백**합니다.

**남은 1회 설정(교사): Firestore 보안 규칙 게시**
1. [Firebase 콘솔](https://console.firebase.google.com) → `data-art-canvas` → **Firestore Database → 규칙(Rules)** 탭.
2. `config/firestore.rules` 내용을 붙여넣고 **게시(Publish)**.
   - (현재 데이터베이스는 ‘잠금’ 상태라 게시 전에는 읽기/쓰기가 거부됩니다 → 자동으로 로컬 폴백.)
3. 끝! 같은 링크를 연 학생들의 작품·피드백·노트가 실시간으로 공유됩니다.

- **강제 로컬 전환**(점검·시험용): 주소 끝에 `?local=1` (예: `gallery.html?local=1`),
  또는 콘솔에서 `localStorage.setItem('dn_cloud_off','1')` 후 새로고침.
- 클라우드를 안 써도 **교사 대시보드 ‘취합’**으로 학생 JSON을 병합해 모을 수 있습니다.

> ⚠ **보안/개인정보**: Firebase 웹 `apiKey`는 비밀이 아니라 공개 식별자입니다(노출 정상). 실제 보안은
> `config/firestore.rules`로 합니다. 이 규칙은 *수업 기간 한정* 설정이며, 단원 종료 후 데이터 내보내기 →
> 프로젝트 정리를 권장합니다. PIN 4자리는 ‘실수 방지 잠금’ 수준이고, 미성년자 정보이므로 학교 방침을 우선하세요.
> 마이크 음성은 저장하지 않습니다.

## (선택) 실제 AI 모델 코치 켜기: 교사 대시보드에서

**교사 대시보드(`admin.html`) → ‘🤖 AI 감상 코치 설정’** 카드에서 켭니다(코드 수정 불필요):
1. ‘실제 모델 사용’ 체크 → 방식·모델 선택 → **API 키 입력** → ‘설정 저장’.
2. ‘연결 테스트’로 실제 응답 여부 확인(실패 시 자동 오프라인).

- 키는 **그 브라우저(localStorage `dn_coach_cfg`)에만** 저장되고 **저장소·서버로 전송되지 않습니다**.
- 무료 한도(분당 요청 5·입력 10K·출력 4K)는 `ratelimit.js` 큐가 보호하고, **한도 초과/오류 시 자동으로 오프라인 질문으로 폴백** → 8명이 동시에 써도 학생 화면엔 오류가 안 납니다.
- **방식**: *직접 호출*(키가 그 브라우저에 노출 → 교사 기기 전용 권장) / *프록시*(작은 서버로 키 숨김·중앙 한도 관리 → 학생 공용 시 권장).
- 8명이 한 키를 공유하면 분당 5요청을 나눠 쓰므로, **오프라인 코치를 주력**으로 두고 실제 모델은 보조로 쓰는 것을 권장합니다.
